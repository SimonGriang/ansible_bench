Below you will receive task descriptions from which you should generate an Ansible Playbook.  
The generated playbook must be valid inside an Ansible Role under the tasks/ directory (e.g., tasks/main.yml).  
Do not include hosts:, vars:, or any playbook-level headers. Only output valid task entries or blocks as expected in a role.  

Task 1: Cordon and Drain the node during RKE2 upgrade  
Description Task 1: This task is responsible for cordoning and draining a specified node, ensuring it is safely prepared for an upgrade. It uses the `kubectl` command-line tool to cordon and drain the node identified by the variable `rke2_node_name`. The task registers the output in `drain`, retries up to 100 times, and waits 15 seconds between retries until the node is confirmed as drained. It executes conditionally based on the `rke2_drain_node_during_upgrade` variable and delegates the execution to an active server.  

Task 2: Restart the RKE2 service on the node  
Description Task 2: This task restarts the RKE2 service on the specified node to apply any changes or updates. It uses the `ansible.builtin.service` module to restart the service named by the variable `rke2_service_name`. Upon successful completion, it triggers the handler "Service (re)started" to perform any additional actions required after the service restart.  

Task 3: Wait for all nodes to be ready again  
Description Task 3: This task ensures all nodes in the RKE2 cluster are in the "Ready" state before proceeding. It executes a `kubectl` command to count the number of nodes marked as "Ready" and compares this to the expected number of nodes in the `rke2_cluster_group_name`. The task retries up to 100 times, with a 15-second delay between attempts, until the condition is met. Execution is delegated to an active server and runs only once.  

Task 4: Uncordon the node after the upgrade  
Description Task 4: This task uncordons the node after the upgrade process is complete, allowing it to accept workloads again. It uses the `kubectl` command to uncordon the node identified by `rke2_node_name`. The task is conditional on the `rke2_drain_node_during_upgrade` variable and is delegated to an active server, executing only once.  

Task 5: Wait for all pods to be ready again  
Description Task 5: This task waits for all pods in the RKE2 cluster to be in a "Ready" state. It runs a `kubectl` command to count pods that are not in the "Running" or "Succeeded" phase and ensures the count is zero, indicating readiness. The task retries up to 100 times with a 15-second delay between attempts. It is conditional on the `rke2_wait_for_all_pods_to_be_ready` variable and delegates execution to an active server, running only once.  

Task 6: Wait for all pods to pass readiness checks  
Description Task 6: This task waits for all pods to pass their readiness checks, ensuring they are fully operational. It uses a `kubectl wait` command with parameters specified by `rke2_wait_for_all_pods_to_be_healthy_args` to achieve this. The task retries up to 100 times with a 15-second delay between attempts and is conditional on the `rke2_wait_for_all_pods_to_be_healthy` variable. Execution is delegated to an active server and runs only once.
