Below you will receive task descriptions from which you should generate an Ansible Playbook.  
The generated playbook must be valid inside an Ansible Role under the tasks/ directory (e.g., tasks/main.yml).  
Do not include hosts:, vars:, or any playbook-level headers. Only output valid task entries or blocks as expected in a role.  

Task 1: Restart RKE2 service on {{ rke2_node_name }}  
Description Task 1: Use the ansible.builtin.service module to restart the RKE2 service named {{ rke2_service_name }}. The task should notify the handler "Service (re)started" after the service has been restarted.  

Task 2: Wait for all nodes to be ready again  
Description Task 2: Execute a shell command that uses {{ rke2_data_path }}/bin/kubectl with the kubeconfig /etc/rancher/rke2/rke2.yaml to list all nodes, filter those that contain " Ready", and count them. Register the result in all_ready_nodes. The task should repeatedly check until the number of ready nodes equals the length of the group groups[rke2_cluster_group_name], retrying up to 100 times with a 15-second delay. It should delegate to the active_server if defined, otherwise to the first server in groups[rke2_servers_group_name], run only once, and only when not in ansible_check_mode.  

Task 3: Wait for all pods to be ready again  
Description Task 3: Run a shell command that uses {{ rke2_data_path }}/bin/kubectl with the kubeconfig /etc/rancher/rke2/rke2.yaml to get all pods across all namespaces whose status.phase is not Running or Succeeded, ignoring not-found errors, and count them. Register the result in all_pods_ready. The task should repeatedly check until the output contains "0", retrying up to 100 times with a 15-second delay. It should delegate to the active_server if defined, otherwise to the first server in groups[rke2_servers_group_name], run only once, and only when not in ansible_check_mode and when the variable rke2_wait_for_all_pods_to_be_ready is true.
