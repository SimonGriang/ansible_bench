Below you will receive task descriptions from which you should generate an Ansible Playbook.  
The generated playbook must be valid inside an Ansible Role under the tasks/ directory (e.g., tasks/main.yml).  
Do not include hosts:, vars:, or any playbook-level headers. Only output valid task entries or blocks as expected in a role.  

Task 1: Cordon and Drain the node {{ rke2_node_name }}  
Description Task 1: Use the shell module to execute kubectl commands that cordon and drain the node identified by the variable `rke2_node_name`. The command is executed via `/bin/bash` with `set -o pipefail`. It uses the binary path stored in `rke2_data_path`, the kubeconfig at `/etc/rancher/rke2/rke2.yaml`, and includes any additional drain arguments from `rke2_drain_additional_args`. The task registers the result as `drain`, retries until the output contains the word “drained” (100 retries, 15‑second delay), is run once, delegates to the host defined in `active_server` or the first host in `groups[rke2_servers_group_name]`, and only runs when the variable `rke2_drain_node_during_upgrade` is true.

Task 2: Restart RKE2 service on {{ rke2_node_name }}  
Description Task 2: Restart the service named by the variable `rke2_service_name` using the service module. The task is notified to trigger the handler labeled “Service (re)started”.

Task 3: Wait for all nodes to be ready again  
Description Task 3: Execute a shell command that counts the number of ready nodes by grepping for “ Ready” in the output of `kubectl get nodes`. The command runs via `/bin/bash`, is not marked as changed, registers the output as `all_ready_nodes`, and retries until the count equals the length of the host group `groups[rke2_cluster_group_name]` (100 retries, 15‑second delay). It runs once and delegates to the host defined in `active_server` or the first host in `groups[rke2_servers_group_name]`.

Task 4: Uncordon the node {{ rke2_node_name }}  
Description Task 4: Use the shell module to run `kubectl uncordon` for the node specified by `rke2_node_name`. The command is executed via `/bin/bash` with `set -o pipefail`, is not marked as changed, runs once, delegates to the host defined in `active_server` or the first host in `groups[rke2_servers_group_name]`, and only executes when `rke2_drain_node_during_upgrade` is true.

Task 5: Wait for all pods to be ready again  
Description Task 5: Run a shell command that counts all pods that are not in the Running or Succeeded phase using `kubectl get pods -A --field-selector=status.phase!=Running,status.phase!=Succeeded --ignore-not-found`. The output is registered as `all_pods_ready`, the task retries until the stdout contains “0” (100 retries, 15‑second delay), is not marked as changed, runs once, delegates to the host defined in `active_server` or the first host in `groups[rke2_servers_group_name]`, and only runs when `rke2_wait_for_all_pods_to_be_ready` is true.

Task 6: Wait for all pods to pass readiness checks  
Description Task 6: Execute a shell command that waits for all pods to pass readiness checks using `kubectl wait` with arguments supplied by `rke2_wait_for_all_pods_to_be_healthy_args`. The command runs via `/bin/bash`, is not marked as changed, retries until successful (100 retries, 15‑second delay), runs once, delegates to the host defined in `active_server` or the first host in `groups[rke2_servers_group_name]`, and only runs when `rke2_wait_for_all_pods_to_be_healthy` is true.
