Below you will receive task descriptions from which you should generate an Ansible Playbook.  
The generated playbook must be valid inside an Ansible Role under the tasks/ directory (e.g., tasks/main.yml).  
Do not include hosts:, vars:, or any playbook-level headers. Only output valid task entries or blocks as expected in a role.  

Task 1: Create the RKE2 config dir  
Description Task 1: Creates the directory `/etc/rancher/rke2` with owner `root`, group `root`, and mode `0755`.  

Task 2: Set server taints  
Description Task 2: Sets the fact `combined_node_taints` to the value of `rke2_server_node_taints` when the variable `rke2_type` equals `'server'`.  

Task 3: Copy rke2 config  
Description Task 3: Copies the template file specified by the variable `rke2_config` to `/etc/rancher/rke2/config.yaml`, sets owner `root`, group `root`, mode `0600`, and notifies the handler `"Config file changed"`.  

Task 4: Copy kubelet config  
Description Task 4: Copies the Jinja2 template `templates/kubelet-config.yaml.j2` to `/etc/rancher/rke2/kubelet-config.yaml` if `rke2_kubelet_config` is non‑empty, sets owner `root`, group `root`, mode `0600`, and notifies `"Config file changed"`.  

Task 5: Copy Containerd Registry Configuration file  
Description Task 5: Copies the template specified by `rke2_custom_registry_path` to `/etc/rancher/rke2/registries.yaml` when either `rke2_custom_registry_mirrors` or `rke2_custom_registry_configs` contain items, sets owner `root`, group `root`, mode `0600`, and notifies `"Config file changed"`.  

Task 6: Register if we need to do a etcd restore from file  
Description Task 6: Sets the fact `do_etcd_restore` to `true` when `rke2_etcd_snapshot_file` is non‑empty and the service `rke2-server.service` is either not defined or disabled.  

Task 7: Register if we need to do a etcd restore from s3  
Description Task 7: Sets the fact `do_etcd_restore_from_s3` to `true` when `rke2_etcd_snapshot_file` is non‑empty and the dictionary `rke2_etcd_snapshot_s3_options` is defined with all required keys (`access_key`, `secret_key`, `bucket`, `snapshot_name`).  

Task 8: Restore etcd from file  
Description Task 8: If `do_etcd_restore` is defined, creates the snapshot directory `{{ rke2_etcd_snapshot_destination_dir }}`, copies the snapshot file from `{{ rke2_etcd_snapshot_source_dir }}` to the destination, and runs `rke2 server` with `--cluster-reset` and `--cluster-reset-restore-path` pointing to the snapshot, using the token `{{ rke2_token }}`.  

Task 9: Restore etcd from s3  
Description Task 9: If `do_etcd_restore_from_s3` is defined, runs `rke2 server` with `--cluster-reset`, `--etcd-s3`, and the appropriate S3 options derived from `rke2_etcd_snapshot_s3_options`, including bucket, access key, secret key, endpoint, region, endpoint CA, folder, and skip SSL verify flags, plus the token `{{ rke2_token }}`.  

Task 10: Start RKE2 service on the first server  
Description Task 10: Starts and enables the service `rke2-server.service`, sets the environment variable `RKE2_TOKEN` to `{{ rke2_token }}`, and notifies the handler `"Service (re)started"`.  

Task 11: Mask RKE2 agent service on the first server  
Description Task 11: Disables and masks the service `rke2-agent.service`.  

Task 12: Wait for the first server be ready - no CNI  
Description Task 12: Executes `kubectl get node "{{ rke2_node_name }}"` and waits until the node reports sufficient memory, no disk pressure, sufficient PID, and either the CNI plugin is not initialized or the kubelet is posting ready status, retrying up to 100 times with a 15‑second delay, only when not in check mode and `rke2_cni` equals `'none'`.  

Task 13: Wait for the first server be ready - with CNI  
Description Task 13: Executes `kubectl get nodes | grep "{{ rke2_node_name }}"` and waits until the output contains `" Ready "`, retrying up to 40 times with a 15‑second delay, only when not in check mode and `rke2_cni` is not `'none'`.  

Task 14: Restore etcd  
Description Task 14: If an etcd restore flag is set, performs the following sub‑tasks:  
- Retrieves the names of registered nodes via `kubectl get nodes --no-headers`.  
- Gathers all node names from the inventory using `hostvars`.  
- Deletes any old node‑password secrets for nodes that are no longer present.  
- Deletes any old node objects for nodes that are no longer present.  

Task 15: Set an Active Server variable  
Description Task 15: Sets the fact `active_server` to the current `inventory_hostname`, delegating this fact collection to every host in the group `{{ groups[rke2_cluster_group_name] }}` with `delegate_facts: true`.
