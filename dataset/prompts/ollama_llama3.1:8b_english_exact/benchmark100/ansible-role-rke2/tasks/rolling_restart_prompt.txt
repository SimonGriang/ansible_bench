Below you will receive task descriptions from which you should generate an Ansible Playbook.

The generated playbook must be valid inside an Ansible Role under the tasks/ directory (e.g., tasks/main.yml).

Do not include hosts:, vars:, or any playbook-level headers. Only output valid task entries or blocks as expected in a role.

Task 1: Cordon and Drain the node with the specified RKE2 node name.
Description Task 1: Cordon and drain the specified RKE2 node to prepare it for maintenance. This task uses the `rke2_data_path` variable to find the kubectl binary, the `rke2_node_name` variable for the node name, and `rke2_drain_additional_args` variable to specify additional drain arguments. The task will retry up to 100 times with a 15-second delay if the node is not fully drained.

Task 2: Restart the RKE2 service on the specified node.
Description Task 2: Restart the RKE2 service on the specified node to ensure it is running with the latest configuration. The task uses the `rke2_service_name` variable to determine the service name.

Task 3: Wait for all nodes to be ready again.
Description Task 3: Wait for all nodes in the cluster to be ready again after maintenance. This task uses the `rke2_data_path` variable to find the kubectl binary and `rke2_cluster_group_name` variable to determine the group of nodes. The task will retry up to 100 times with a 15-second delay if all nodes are not ready.

Task 4: Uncordon the specified RKE2 node.
Description Task 4: Uncordon the specified RKE2 node to allow it to receive new workloads. This task uses the `rke2_data_path` variable to find the kubectl binary and `rke2_node_name` variable for the node name.

Task 5: Wait for all pods to be ready again.
Description Task 5: Wait for all pods in the cluster to be ready again after maintenance. This task uses the `rke2_data_path` variable to find the kubectl binary and will retry up to 100 times with a 15-second delay if all pods are not ready.

Task 6: Wait for all pods to pass readiness checks.
Description Task 6: Wait for all pods in the cluster to pass their readiness checks after maintenance. This task uses the `rke2_data_path` variable to find the kubectl binary and `rke2_wait_for_all_pods_to_be_healthy_args` variable to specify the wait arguments. The task will retry up to 100 times with a 15-second delay if all pods are not healthy.
