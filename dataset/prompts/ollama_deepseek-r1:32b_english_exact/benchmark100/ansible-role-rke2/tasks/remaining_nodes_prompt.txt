Below you will receive task descriptions from which you should generate an Ansible Playbook.  
The generated playbook must be valid inside an Ansible Role under the tasks/ directory (e.g., tasks/main.yml).  
Do not include hosts:, vars:, or any playbook-level headers. Only output valid task entries or blocks as expected in a role.  

Task 1: Create the RKE2 config directory  
Description Task 1: Create the directory /etc/rancher/rke2 with root ownership and mode 0755.

Task 2: Set server node taints  
Description Task 2: Set the combined_node_taints fact to rke2_server_node_taints when the node type is server.

Task 3: Set agent node taints  
Description Task 3: Set the combined_node_taints fact to rke2_agent_node_taints when the node type is agent.

Task 4: Copy RKE2 config file  
Description Task 4: Copy the RKE2 configuration file from the specified source to /etc/rancher/rke2/config.yaml with root ownership and mode 0600, and notify the Config file changed handler.

Task 5: Copy kubelet config  
Description Task 5: Copy the kubelet configuration file from templates/kubelet-config.yaml.j2 to /etc/rancher/rke2/kubelet-config.yaml with root ownership and mode 0600, if rke2_kubelet_config is not empty, and notify the Config file changed handler.

Task 6: Copy Containerd Registry Configuration file  
Description Task 6: Copy the Containerd Registry Configuration file from the specified path to /etc/rancher/rke2/registries.yaml with root ownership and mode 0600, if custom registry mirrors or configs are present, and notify the Config file changed handler.

Task 7: Start RKE2 service  
Description Task 7: Start and enable the RKE2 service with retries and delays, setting the RKE2_TOKEN environment variable, and continue until the service starts successfully.

Task 8: Mask other RKE2 services  
Description Task 8: Mask and disable the RKE2 services for the other node type (agent or server) using a loop over the list of services excluding the current node type.

Task 9: Wait for remaining nodes to be ready - no CNI  
Description Task 9: Wait for nodes to be ready by checking specific conditions in node_status.stdout_lines, with retries and delays, and only run on the active server or first server node when rke2_cni is set to none.

Task 10: Wait for remaining nodes to be ready - with CNI  
Description Task 10: Wait for all nodes to be ready by checking the count of Ready nodes, with retries and delays, and only run on the active server or first server node when rke2_cni is not none and not in check mode.
