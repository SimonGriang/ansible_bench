Below you will receive task descriptions from which you should generate an Ansible Playbook.  
The generated playbook must be valid inside an Ansible Role under the tasks/ directory (e.g., tasks/main.yml).  
Do not include hosts:, vars:, or any playbook-level headers. Only output valid task entries or blocks as expected in a role.  

Task 1: Create Vault group  
Description Task 1: Create a system group with the name specified by the vault_group variable using the group module.

Task 2: Create Vault user  
Description Task 2: Create a system user with the name specified by the vault_user variable, without a home directory, using the shell specified by vault_user_shell, and assign it to the group specified by vault_group.

Task 3: Create Vault download directory  
Description Task 3: Create a directory at the path specified by vault_download_path with ownership set to the Vault user and group, and permissions set to 0755.

Task 4: Download Vault binary  
Description Task 4: Download and extract the Vault binary from the specified URL into the directory specified by vault_download_path. The URL includes variables for version and architecture. The extracted binary is owned by root with permissions 0644.

Task 5: Check if vault_path exists  
Description Task 5: Use the stat module to check if the directory specified by vault_path exists and register the result.

Task 6: Create vault_path if it does not exist  
Description Task 6: Create the directory specified by vault_path if it does not exist, with ownership set to the Vault user and group, and permissions set to 0755.

Task 7: Create directories in vault_path  
Description Task 7: Loop through the list specified by vault_directories and create each directory with the specified owner, group, and mode.

Task 8: Create data directories  
Description Task 8: Loop through the list specified by vault_data_directories and create each directory with the specified owner, group, and mode.

Task 9: Generate TLS key and certificate  
Description Task 9: Generate a TLS key and certificate in the directory specified by vault_data_directory/tls/ using openssl. The certificate is valid for 1095 days and notifies a restart of the Vault service.

Task 10: Set ownership of TLS files  
Description Task 10: Loop through the list specified by vault_tls_files and set the ownership, group, and mode for each file.

Task 11: Copy Vault binary  
Description Task 11: Copy the Vault binary from the download directory to the final destination specified by vault_path/usr/bin/vault, owned by root with permissions 0755. Notifies a restart of the Vault service.

Task 12: Set capabilities on Vault binary  
Description Task 12: Set the cap_ipc_lock capability on the Vault binary with the +ep flag using the capabilities module.

Task 13: Touch vault.env file  
Description Task 13: Create an empty file at vault_path/etc/vault.d/vault.env with ownership set to the Vault user and group, and permissions set to 0644. Notifies a restart of the Vault service.

Task 14: Create systemd directory  
Description Task 14: Ensure the directory /usr/lib/systemd/system exists with ownership set to root and permissions set to 0755.

Task 15: Copy Vault service file  
Description Task 15: Copy the Vault service file from the template vault.service.j2 to /usr/lib/systemd/system/vault.service, owned by root with permissions 0644. Only runs if the system uses systemd and notifies a daemon reload.

Task 16: Copy Vault configuration  
Description Task 16: Copy the Vault configuration file vault.hcl to the directory specified by vault_path/etc/vault.d/vault.hcl, owned by root with permissions 0644. Only runs if the file does not exist and notifies a restart of the Vault service.

Task 17: Flush handlers  
Description Task 17: Flush all pending handlers to ensure all notifications are processed.
